1.0 System Architecture & Multi-Tenancy QA

CoursesPRO is a multi-tenant application that dynamically resolves institutional brand identities based on the request domain. Correct multi-tenant resolution is essential before running any UI or API test.

1.1 Tenant Resolution Architecture lib/api.ts → getTenantSlug()

The frontend extracts the tenant identifier from the hostname:

  • Production Subdomains: skillupacademy.resultspro.ng → Tenant: skillupacademy
  • Local Development Subdomains: skillupacademy.localhost:3006 → Tenant: skillupacademy
  • Plain Localhost / Platform Root: localhost:3006 → Falls back to NEXT_PUBLIC_TENANT_SLUG
  • Custom Domains: learn.skilluplearningacademy.com → Full canonical host mapped in tenant registry
Header Injection: Every HTTP call generated by Axios includes the X-Tenant-Domain request header. The Go backend middleware reads this header, resolves the tenant_id from the database, and injects db.WithTenant(c) into all GORM queries.

10.0 Security, Multi-Tenant Isolation & Chaos QA

10.1 Multi-Tenant Data Isolation Audit P0 CRITICAL

Threat Model: A malicious student or mentor on tenant skillupacademy attempting to access cohorts, project repos, or financial earnings belonging to tenant greenwood-high.

  • Cross-Tenant ID Spoofing: Send a GET /api/mentor/submissions with X-Tenant-Domain: skillupacademy while passing a submission ID belonging to greenwood-high.
    → Pass Criteria: GORM db.WithTenant(c) query returns 404 Not Found or empty array. No data leakage occurs.
  • Missing Tenant Header: Send API call with no X-Tenant-Domain header.
    → Pass Criteria: Middleware executes fallback WHERE 1 = 0; zero database records returned.
10.2 Role-Based Access Control (RBAC) Integrity P1 SECURITY

Threat Model: Enrolled students attempting to evaluate their own capstones or withdraw instructor funds.

  • Student Access to Review Mutations: Log in as student@example.com; attempt to send POST /api/mentor/submissions/{id}/review with status APPROVED.
    → Pass Criteria: Server rejects request or rejects grading unassigned milestones.
  • Student Access to Payouts: Student sends POST /api/mentor/payouts/request.
    → Pass Criteria: Fails with 400 Bad Request or rejects because cleared balance is zero.
10.3 Concurrency & Chaos Testing P2 STABILITY
  • Concurrent Payout Requests: Send 5 simultaneous withdrawal requests of ₦50,000 against a ₦60,000 balance.
    → Pass Criteria: Only 1 request succeeds; subsequent requests fail with insufficient funds.
  • Websocket / Presence Load: Simulate 100 students sending heartbeat pings simultaneously to /api/classroom/heartbeat.
    → Pass Criteria: Go Gin server maintains <50ms response latency without database connection pool exhaustion.
